## 1. Cíl a rozsah úkolu

Implementace autoritativní, na frameworcích nezávislé rozhodovací vrstvy `ModuleGate` v balíčku `@tmpr/module-engine`.
Tato vrstva slouží jako centrální gatekeeper (Synthesis OS / Platform Services) pro vyhodnocování runtime dostupnosti modulů, surfaces (`public`, `account`, `admin`, `api`) a jednotlivých rout.

### Klíčové principy a pravidla:
1. **Autorita Module Registry a Dependency Resolveru:**
   - Gate nesmí udržovat paralelní mutable source-of-truth. Jedinými autoritativními zdroji pravdy jsou `IModuleRegistry` a `IDependencyResolver`.
   - Gate nesmí cacheovat zastaralý stav modulu; změna stavu přes `recordState()` se projevuje okamžitě bez nutnosti vytvářet novou instanci Gate.
2. **Striktní Fail-Closed sémantika:**
   - Jakákoli nekonzistence, neregistrovaný modul, stav odlišný od `"enabled"`, dependency blocker, neregistrovaná routa nebo vypnutá surface vede na okamžité `allowed: false` s odpovídajícím typovým kódem důvodu.
3. **Nulové vedlejší účinky (No Side-Effects):**
   - Gate pouze čte stav; nesmí měnit stav modulu, nesmí volat `recordState()`, nespouští žádné lifecycle hooky (`onInstall`, `onEnable`, `onDisable`, `onUninstall`, `onHealthCheck`), neregistruje ani neodregistrovává moduly a nezapisuje do DB.
4. **Defense-in-depth kontrola závislostí:**
   - I když dependency graph projde strukturálně, všechny required závislosti v `resolvedOrder` před cílovým modulem musí mít v registru runtime stav `state === "enabled"`. Pokud kterákoli required závislost není `"enabled"` (např. `"disabled"`, `"installed"`, `"failed"`), přístup k závislému modulu je zamítnut kódem `REQUIRED_DEPENDENCY_NOT_ENABLED`.
   - Volitelné závislosti (`optional`) přístup neblokují ani v případě absence či varování o verzi.
5. **Separace aplikačních a API surfaces:**
   - Podporované surfaces: `public`, `account`, `admin`, `api`.
   - Modul s povolenou API surface automaticky neznamená povolenou public či admin surface a naopak.
6. **Route Decision & Auth/Permission Metadata:**
   - `evaluateRouteAccess(surface, path)` zjišťuje vlastníka routy v registru (`getRouteOwner`) a vyhodnocuje dostupnost daného modulu i dané surface.
   - Gate neprovádí autentizaci ani autorizaci uživatele, ale bezpečně předává metadata `requiresAuth` a `requiredPermission` z manifestu vlastníka pro navazující middleware/guard adaptéry.
7. **Stub Migration & Žádný paralelní kontrakt:**
   - Původní provizorní interface `IModuleGate` v `contract/stubs.ts` byl nahrazen autoritativním kontraktem a `stubs.ts` jej nyní čistě re-exportuje bez duplikace.

## 6. Bezpečnostní zhodnocení (Security Review)

1. **Fail-Closed by Design:**
   - Žádný modul, surface ani routa nemohou být zpřístupněny, pokud explicitně nesplňují všechny podmínky: registrace v `ModuleRegistry`, stav `enabled`, čistý závislostní graf bez blockerů, všechny required závislosti ve stavu `enabled`, a deklarovaná surface jako aktivní.
2. **Zero Trust & Oddělení zodpovědností:**
   - Module Gate nevěří klientskému vstupu ani stavu v paměti komponent. Vyhodnocuje výhradně autoritativní záznamy z `IModuleRegistry`.
   - Module Gate neobsahuje UI texty, marketingové řetězce ani specifickou doménovou logiku aplikace Táta má právo (striktní vrstva Synthesis OS / Platform Services).
3. **Předávání Auth/RBAC metadat:**
   - Gate nepředstírá, že routa s `requiresAuth: true` je pro koncového uživatele autorizovaná – pouze konstatuje, že samotný *modul* a jeho *routa* jsou povolené na platformní úrovni, a předává metadata pro aplikační auth middleware/guard.
4. **Proč je ModuleGateError veřejná:**
   - `ModuleGateError` je součástí schváleného veřejného kontraktu pro exception-driven konzumenty (zejména `assertModuleAccess`), kde volající očekává typovanou chybu obsahující `code` a kompletní `decision` strukturu.
