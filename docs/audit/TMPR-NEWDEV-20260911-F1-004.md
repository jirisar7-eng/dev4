## 1. Cíl a rozsah úkolu

Implementace autoritativního, projektově neutrálního `DependencyResolver` v balíčku `@tmpr/module-engine` pro vyhodnocování závislostí modulů, kontrolu kompatibility verzí (SemVer ranges), deterministickou detekci cyklů a sestavení bezpečného pořadí aktivace (topological sort).

### Klíčové principy a pravidla:
1. **Autorita Module Registry:** Resolver pracuje výhradně s autoritativními daty z `IModuleRegistry` (`listRecords()`), nikoli s nespolehlivým runtime stavem či nestrukturovaným `module.manifest`.
2. **Striktní Read-only chování:** Resolver nemění stav registru, nemění manifesty, nevolá `recordState()`, neregistruje ani neodregistrovává moduly.
3. **Fail-closed sémantika:** Pokud existuje jakýkoli blocker (chybějící povinná závislost, nekompatibilní SemVer, cyklus v povinných závislostech, neregistrovaný cílový modul), resolver vrátí `ok: false` a `resolvedOrder: []` (žádné částečné pořadí).
4. **Rozlišení Required vs Optional:**
   - **Required závislosti:** tvoří tvrdý orientovaný graf; chybějící či nekompatibilní závislost je BLOCKER; cyklus je BLOCKER.
   - **Optional závislosti:** nevytvářejí blokující chyby ani cykly; chybějící či nekompatibilní volitelná závislost generuje ADVISORY a nebrání sestavení pořadí.
5. **Algoritmická robustnost a determinismus:**
   - Detekce cyklů: Tarjanův algoritmus silně souvislých komponent (SCC) $O(V + E)$ v kombinaci s BFS pro nalezení nejkratšího kanonického witness cyklu (žádné exponenciální výčty cyklů).
   - Normalizace cyklů (`canonicalizeCycle`): cykly rotovány k lexikografickému minimu (např. `[B, C, A, B]` -> `[A, B, C, A]`), zamezení duplicitním chybám.
   - Topologické řazení: Kahnův algoritmus s prioritní frontou seřazenou lexikograficky pro deterministické výsledky nezávislé na pořadí registrace modulů. Závislosti jsou vždy řazeny PŘED závislými moduly (`[C, B, A]` kde A requires B, B requires C).
6. **Izolace analýzy v `resolveFor(moduleKey)`:** Vyhodnocuje pouze cílový modul a jeho dosažitelný uzávěr povinných závislostí. Chyby v nesouvisejících modulech tento výsledek neblokují.
7. **Globální analýza v `resolveAll()`:** Analyzuje všechny registrované moduly, detekuje oddělené cyklické komponenty a sestaví globální pořadí aktivace.

## 3. Detailní rozhraní a datový model

```typescript
export type DependencyIssueCode =
  | "TARGET_NOT_REGISTERED"
  | "MISSING_REQUIRED_DEPENDENCY"
  | "REQUIRED_VERSION_INCOMPATIBLE"
  | "DEPENDENCY_CYCLE"
  | "OPTIONAL_DEPENDENCY_MISSING"
  | "OPTIONAL_VERSION_INCOMPATIBLE";

export type DependencyIssueSeverity = "blocker" | "advisory";

export interface DependencyIssue {
  readonly code: DependencyIssueCode;
  readonly severity: DependencyIssueSeverity;
  readonly message: string;
  readonly moduleKey: string;
  readonly dependencyKey?: string;
  readonly requiredRange?: string;
  readonly actualVersion?: string;
  readonly cycle?: readonly string[];
}

export interface DependencyResolutionResult {
  readonly ok: boolean;
  readonly resolvedOrder: readonly string[];
  readonly blockers: readonly DependencyIssue[];
  readonly advisories: readonly DependencyIssue[];
  readonly cycles: readonly (readonly string[])[];
}

export interface IDependencyResolver {
  resolveFor(moduleKey: string): DependencyResolutionResult;
  resolveAll(): DependencyResolutionResult;
}
```

## 5. Bezpečnostní a architektonické hodnocení (DevSecOps)

- **Žádné hardcoded secrets ani externí závislosti:** Použity výhradně knihovny `semver` a nativní datové struktury Node.js.
- **Fail-closed:** Při jakékoli nesrovnalosti je vrácen prázdný `resolvedOrder`, čímž je vyloučena částečná nebo nebezpečná aktivace v navazujícím Lifecycle Engine.
- **Zero Side-Effects:** Resolver operuje nad read-only snapshoty z `IModuleRegistry` a negeneruje žádné vedlejší efekty v databázi ani v paměti registru.
- **Odolnost proti DoS:** Cykly v závislostech jsou detekovány v lineárním čase $O(V + E)$ bez rekurzivního přetečení zásobníku či exponenciálního prohledávání.
