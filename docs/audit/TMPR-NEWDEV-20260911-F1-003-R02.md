## 1. Problém původní implementace (Boundary Leak & Reference Sharing)

Předchozí revize R01 úspěšně vyřešila přímou mutaci `record.state` zavedením odděleného `InternalModuleRegistryRecord` a neměnných snapshotů vrácených z `getRecord()` a `listRecords()`.

Nicméně autoritativní snapshot stále sdílel referenci na objekt manifestu a tento manifest byl v `register()` zmrazen pouze na první úrovni (shallow freeze):
```typescript
const manifest = Object.freeze({ ...validation.data });
```

Důsledkem této neúplné ochrany bylo:
1. Vnořená pole a objekty v manifestu zůstaly mutable:
   - `record.manifest.routes.push(...)`
   - `record.manifest.dependencies.required.push(...)`
   - `(record.manifest.surfaces as any).api.enabled = false`
2. Původní objekt předaný v `module.manifest` nebyl oddělen, takže případná mutace původního manifestu volajícím kódem po registraci mohla ovlivnit autoritativní data registru.

## 2. Architektonické řešení

Pro zajištění absolutní integrity dat a neměnnosti autoritativního stavu bylo implementováno řešení na dvou úrovních (Type-level i Runtime-level):

### 2.1. Type-level Immutability (`DeepReadonly<T>`)
V souboru `packages/module-engine/src/registry/registry.types.ts` byl definován rekurzivní typový operátor:
```typescript
export type DeepReadonly<T> = T extends Function | boolean | number | string | symbol | bigint | null | undefined
  ? T
  : T extends (infer R)[]
  ? ReadonlyArray<DeepReadonly<R>>
  : T extends readonly (infer R)[]
  ? ReadonlyArray<DeepReadonly<R>>
  : T extends object
  ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
  : T;
```
Veřejné rozhraní `IModuleRegistryRecord` nyní definuje manifest jako:
```typescript
readonly manifest: DeepReadonly<IModuleManifest>;
```
Tím statický typový systém TypeScriptu striktně zakazuje volání mutačních metod (jako `.push()`, `.splice()`) i přímé přiřazení do vnořených vlastností.

### 2.2. Runtime Immutability & Deep Freeze (`deepFreeze`)
V novém modulu `packages/module-engine/src/registry/registry.utils.ts` byla vytvořena čistá pomocná funkce `deepFreeze`:
- Rekurzivně prochází všechny vlastnosti objektů a polí a volá `Object.freeze`.
- Obsahuje ochranu proti uváznutí v cyklických odkazech pomocí `WeakSet`.
- Nevyužívá žádné runtime proxies.

### 2.3. Izolace a uložení v registru (`ModuleRegistry.register`)
Metoda `register()` v `packages/module-engine/src/registry/registry.ts`:
1. Po úspěšné validaci přes `safeValidateModuleManifest` provede hluboké klonování validovaných dat pomocí standardního `structuredClone(validation.data)`.
2. Klon je okamžitě hluboce zmrazen přes `deepFreeze(manifestClone)`.
3. Interní záznam `InternalModuleRegistryRecord` ukládá tento hluboce zmrazený klon.
4. Tím je garantováno:
   - Změna původního `module.manifest` po registraci nijak neovlivní data v registru.
   - Jakýkoli pokus o mutaci vnořených položek ve snapshotu z `getRecord()` nebo `listRecords()` vyvolá v Node.js strict mode `TypeError`.
   - Autoritativní registry snapshot je 100% izolován.
