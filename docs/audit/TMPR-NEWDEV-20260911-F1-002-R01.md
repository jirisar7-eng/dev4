## 2. Oprava diagnózy: Classic PAT vs. Fine-Grained PAT

- **Předchozí hypotéza:** Hypotéza, že token je Fine-Grained Personal Access Token s omezením na "Selected repositories" a chybějícím repozitářem `dev4`, byla **chybná a byla zcela opuštěna**.
- **Autoritativní zjištění:** Používaný autentizační údaj je **Classic Personal Access Token** uživatele `jirisar7-eng` s plnou sadou scopes:
  `admin:enterprise, admin:gpg_key, admin:org, admin:org_hook, admin:public_key, admin:repo_hook, admin:ssh_signing_key, codespace, copilot, delete:packages, gist, notifications, project, read:audit_log, repo, user, workflow, write:discussion, write:network_configurations, write:packages`.

---

## 3. Zjištění k původní chybě HTTP 403 (Korekce root cause)

1. Původní `git push` vrátil HTTP 403.
2. Classic PAT byl následně nezávisle ověřen vůči GitHub REST API.
3. Zápisová a administrátorská oprávnění (`push: true`, `admin: true`) pro účet `jirisar7-eng` na repozitáři `dev4` byla následně ověřena.
4. Pozdější `git push` proběhl zcela úspěšně s návratovým kódem 0.
5. Přesná interní příčina prvního odmítnutí HTTP 403 nebyla nezávisle prokázána.
6. Možné zpoždění propagace oprávnění (replication / propagation delay) na infrastruktuře GitHubu bezprostředně po založení prázdného repozitáře zůstává pouze neověřenou hypotézou, nikoliv potvrzeným faktem. Audit netvrdí interní stav infrastruktury GitHubu bez přímých důkazů.
