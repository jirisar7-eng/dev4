## 1. Problém původní implementace (Boundary Leak)

Ve fázi F1-003 metody `getRecord(moduleKey)` a `listRecords()` vracely přímo interní instanci `IModuleRegistryRecord`. Tato struktura měla mutable property `state: ModuleLifecycleState`.
Důsledkem bylo, že externí kód mohl přímo mutovat `record.state = "enabled"` a tím obejít autoritativní kontrolní bod `recordState(moduleKey, state)`.

---

## 2. Způsob oddělení Internal vs Public Record

1. **`InternalModuleRegistryRecord`**:
   - Striktně interní privátní interface v `packages/module-engine/src/registry/registry.ts`.
   - Není exportován do veřejného API balíčku `@tmpr/module-engine`.
   - Obsahuje mutable položku `state: ModuleLifecycleState`.
   - Je spravován v interní mapě `private readonly records = new Map<string, InternalModuleRegistryRecord>()`.

2. **`IModuleRegistryRecord`**:
   - Autoritativní veřejné rozhraní v `packages/module-engine/src/registry/registry.types.ts`.
   - Všechny položky včetně `state` jsou deklarovány jako `readonly`:
     `readonly state: ModuleLifecycleState;`

3. **Bezpečné snapshoty (`toPublicRecord`)**:
   - `getRecord(moduleKey)` vrací nový objekt vytvořený přes `this.toPublicRecord(internal)`.
   - Snapshot je zmrazen pomocí `Object.freeze(...)`.
   - Případný pokus o mutaci vráceného objektu v strict-mode vyvolá `TypeError` a v non-strict mode neovlivní interní instanci v registru.
   - `listRecords()` mapuje všechny interní záznamy na samostatné snapshoty a vrací zmrazené pole (`Object.freeze(...)`).
   - `list()` vrací zmrazené pole instancí modulů.
   - Při registraci je manifest zmrazen (`Object.freeze({ ...validation.data })`).

4. **Autoritativní změna stavu**:
   - `recordState(moduleKey, state)` zůstává jedinou autoritativní cestou k aktualizaci stavu životního cyklu v registru.
   - Nespouští žádné lifecycle hooky.
