## 2. PŘEHLED A VERIFIKACE 4 POVINNÝCH OPRAV

### 2.1 Oprava 1: Vlastnictví Brandu (Brand Ownership)
- **Požadavek:** Vizuální autorita `TMPR-BRAND-BLUE-1.0` a logo asset `brand.tata-ma-pravo.logo.source` patří POUZE projektu `projectKey=tata-ma-pravo`. Nesmí být globálním Synthesis balíčkem. Brand Pack musí být svázán s `packages/project-tata-ma-pravo`. Synthesis OS, CMS, Admin a Control Plane zůstávají brandově neutrální.
- **Nález před revizí:** `packages/brand-blue` existoval jako samostatný globální balíček v `packages/` a `packages/ui` na něm byl závislý.
- **Implementovaná oprava:**
  - Balíček `packages/brand-blue` byl zrušen jako globální entita Synthesis platformy.
  - Vizuální autorita a tokeny `TMPR-BRAND-BLUE-1.0` spolu s logem `brand.tata-ma-pravo.logo.source` byly plně svázány s `packages/project-tata-ma-pravo/brand`.
  - `packages/ui` byl redefinován jako brandově neutrální komponentový systém platformy Synthesis OS (řízený neutrálními CSS proměnnými).
  - Synthesis Admin (`apps/admin`), Synthesis CMS (`packages/synthesis-cms`) a Control Plane mají explicitně zakázán import Brand Packu (`ERR-ARCH-004`) a zůstávají neutrální.
- **Stav:** ✅ **BRAND OWNERSHIP FIXED: YES**

---

### 2.2 Oprava 2: Vlastnictví Databáze (Database Ownership)
- **Požadavek:** Každý doménový modul vlastní své schéma, své migrace a svá data. Centrální DB vrstva pouze skládá Prisma schéma/klienta a řídí migrace. Nesmí zrušit Single Owner pravidlo modulů.
- **Nález před revizí:** `packages/db` obsahoval popis monolitického schématu a migrací, což stíralo hranice vlastnictví tabulek jednotlivými doménovými moduly.
- **Implementovaná oprava:**
  - Každý doménový modul v `modules/<name>/` má dedikovaný adresář `prisma/schema.prisma` a `prisma/migrations/`.
  - Centrální balíček `packages/db` je redefinován jako **kompozitní vrstva**: automaticky skládá schémata modulů do jednotného klienta a koordinuje běh migrací.
  - Zakotveno striktní **Single Owner & Writer Rule**: Žádný modul nesmí číst ani zapisovat do cizích tabulek přímo, nýbrž výhradně přes deklarované veřejné servisní kontrakty (`@tmpr/<name>/contract`).
- **Stav:** ✅ **MODULE DATA OWNERSHIP FIXED: YES**

---

### 2.3 Oprava 3: Zařazení Module Engine do vrstev architektury (Module Engine Layer)
- **Požadavek:** Module Engine patří do `Synthesis OS / Platform Services`. Autoritativní hierarchie vrstev:
  `Synthesis OS` → `Synthesis CMS` → `Project Package` → `Domain Modules`.
  Závislosti smějí směřovat POUZE k nižší obecnější vrstvě.
- **Nález před revizí:** Module Engine byl umístěn volně bez explicitního vyjádření autoritativního toku závislostí vůči CMS a projektovým balíčkům.
- **Implementovaná oprava:**
  - `packages/module-engine` je explicitně zařazen jako součást `Synthesis OS / Platform Services`.
  - Definována striktní jednosměrná hierarchie závislostí:
    1. `Domain Modules` smějí záviset na Project Package, Synthesis CMS a Synthesis OS.
    2. `Project Package` smí záviset na Synthesis CMS a Synthesis OS.
    3. `Synthesis CMS` smí záviset na Synthesis OS.
    4. `Synthesis OS` (Core, Module Engine, UI) nesmí záviset na žádné vyšší vrstvě (`ERR-ARCH-001`, `ERR-ARCH-002`, `ERR-ARCH-003`).
- **Stav:** ✅ **MODULE ENGINE LAYER FIXED: YES**

---

### 2.4 Oprava 4: Odstranění BullMQ / Redis ze základu (Postgres Queue)
- **Požadavek:** Odstranit z architektonického základu BullMQ a Redis. První verze používá: `PostgreSQL-backed queue + apps/worker`. Redis lze přidat později pouze samostatným Architecture Decision.
- **Nález před revizí:** `apps/worker` a sekce technologického stacku zmiňovaly BullMQ a Redis jako standardní součást frontového systému.
- **Implementovaná oprava:**
  - Všechny reference na BullMQ a Redis byly odstraněny z architektonické specifikace.
  - Jako autoritativní asynchronní fronta pro `apps/worker` byla zavedena **PostgreSQL-backed queue** (využívající stávající instanci PostgreSQL 16 a transakční zpracování úloh).
  - V pravidlech `ERR-ARCH-008` a sekci CI kontrol byl zaveden zákaz balíčků `bullmq` a `ioredis` v této fázi. Zavedení Redisu je možné výhradně na základě budoucího samostatného Architecture Decision (ADR).
- **Stav:** ✅ **POSTGRES QUEUE FIXED: YES**
